Câu 1: position: absolute và position: relative

1.1. Sự khác biệt

Trong CSS, position: relative giữ nguyên vị trí ban đầu của phần tử trong luồng tài liệu. Khi sử dụng các thuộc tính top, right, bottom, left, phần tử có thể được dịch chuyển so với vị trí ban đầu.

Trong khi đó, position: absolute đưa phần tử ra khỏi luồng tài liệu thông thường. Phần tử được định vị dựa trên phần tử cha gần nhất có position khác static. Nếu không có phần tử cha phù hợp, nó sẽ được định vị theo viewport.

1.2. Ví dụ position: relative

Relative

Phần tử vẫn giữ vị trí trong layout.

1.3. Ví dụ position: absolute

Absolute

Phần tử Absolute được định vị dựa trên phần tử cha.

1.4. Ứng dụng Responsive

Relative thường được sử dụng để tạo phần tử cha làm mốc định vị cho các phần tử con.

Absolute phù hợp với các thành phần như icon nằm trên hình ảnh, badge thông báo, nút đóng hoặc menu phụ.

Khi website responsive, nên hạn chế sử dụng absolute với kích thước cố định vì layout có thể bị lệch trên màn hình nhỏ. Có thể kết hợp CSS Grid, Flexbox, %, rem và media query để đảm bảo tương thích.

1.5. Ảnh hưởng khi deploy lên hosting

position relative và absolute được xử lý bởi trình duyệt nên không phụ thuộc trực tiếp vào hosting. Tuy nhiên, website phải được thiết kế responsive để hiển thị đúng trên desktop, tablet và smartphone.

Câu 2: Domain, Hosting và DNS

2.1. Domain là gì?

Domain là tên miền giúp người dùng truy cập website dễ dàng thay vì phải nhớ địa chỉ IP của máy chủ. Ví dụ: example.com.

2.2. Hosting là gì?

Hosting là nơi lưu trữ các file của website như HTML, CSS, JavaScript, hình ảnh và các tài nguyên khác.

2.3. Quy trình đăng ký Domain và Hosting

  1. Chọn một tên domain phù hợp.
  2. Kiểm tra domain còn khả dụng hay không.
  3. Đăng ký và thanh toán tên miền.
  4. Chọn dịch vụ hosting hoặc nền tảng deploy.
  5. Upload source code HTML, CSS và JavaScript.
  6. Cấu hình DNS để domain trỏ tới hosting.
  7. Kiểm tra website bằng domain.

2.4. Vai trò của DNS

DNS (Domain Name System) có nhiệm vụ chuyển đổi tên miền thành địa chỉ IP hoặc thông tin định tuyến phù hợp để trình duyệt có thể tìm đến máy chủ chứa website.

2.5. Công cụ deploy

  • GitHub Pages: phù hợp với website tĩnh sử dụng HTML, CSS và JavaScript.
  • Netlify: hỗ trợ deploy website tĩnh nhanh chóng, kết nối với GitHub và tự động cập nhật khi source code thay đổi.

2.6. Rủi ro bảo mật

  • Không sử dụng HTTPS có thể khiến dữ liệu truyền giữa người dùng và website bị nghe lén.
  • Cấu hình DNS sai có thể làm website không truy cập được hoặc trỏ đến hệ thống không mong muốn.
  • Đưa API key hoặc mật khẩu vào JavaScript phía client có thể làm lộ thông tin.
  • Source code có lỗ hổng XSS có thể cho phép mã độc chạy trong trình duyệt người dùng.

Câu 3: So sánh let, const và var

Đặc điểm var let const
Scope Function scope Block scope Block scope
Có thể gán lại Có Có Không
Hoisting Có, giá trị undefined Có nhưng nằm trong TDZ Có nhưng nằm trong TDZ

3.1. Ví dụ lỗi với var


      for (var i = 0; i < 3; i++) {
          console.log(i);
      }
      
      console.log(i);
      
      // Kết quả: 3

Vì var không có block scope nên biến i vẫn tồn tại bên ngoài vòng lặp.

3.2. Ví dụ với let


      for (let i = 0; i < 3; i++) {
          console.log(i);
      }
      
      console.log(i);
      
      // ReferenceError

let có block scope nên i chỉ tồn tại trong vòng lặp.

3.3. Ví dụ với const


      const name = "Hung";
      
      name = "An";
      
      // TypeError

const không cho phép gán lại giá trị cho biến.

3.4. Debug bằng Chrome DevTools

Có thể mở Chrome DevTools bằng phím F12 hoặc Ctrl + Shift + I.

Tab Console cho phép xem lỗi JavaScript. Tab Sources cho phép đặt breakpoint, chạy từng dòng lệnh và kiểm tra giá trị biến.

Khi xảy ra lỗi, DevTools hiển thị loại lỗi, dòng code gây lỗi và stack trace để hỗ trợ tìm nguyên nhân.

Câu 4: Event Delegation trong JavaScript

4.1. Khái niệm

Event Delegation là kỹ thuật gắn một event listener cho phần tử cha thay vì gắn riêng listener cho từng phần tử con.

Kỹ thuật này dựa trên cơ chế Event Bubbling của JavaScript. Khi người dùng click vào phần tử con, sự kiện sẽ bubble lên phần tử cha.

4.3. JavaScript Event Delegation


      productList.addEventListener("click", function(event) {
      
          if (event.target.classList.contains("delete")) {
      
              event.target.parentElement.remove();
      
          }
      
      });

Ở đây chỉ cần một event listener cho productList, thay vì tạo một event listener riêng cho từng nút Xóa.

4.4. Lợi ích

  • Giảm số lượng event listener.
  • Tiết kiệm bộ nhớ.
  • Tăng hiệu suất khi danh sách có nhiều phần tử.
  • Có thể xử lý các phần tử được tạo động sau khi trang đã tải.
  • Code JavaScript ngắn gọn và dễ bảo trì hơn.

4.5. Kết hợp HTML/CSS

HTML chịu trách nhiệm xây dựng cấu trúc danh sách, CSS chịu trách nhiệm hiển thị và responsive, còn JavaScript xử lý sự kiện.

Việc phân chia HTML, CSS và JavaScript thành các nhiệm vụ riêng giúp website dễ bảo trì và tối ưu hiệu suất khi deploy.
