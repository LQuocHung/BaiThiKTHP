Phân biệt position: relative và position: absolute

1. Position: relative

Phần tử được định vị tương đối so với vị trí ban đầu của chính nó. Khi sử dụng top, right, bottom hoặc left, phần tử có thể dịch chuyển nhưng vẫn giữ chỗ trong luồng bố cục ban đầu.

2. Position: absolute

Phần tử được định vị theo phần tử tổ tiên gần nhất có thuộc tính position khác static. Phần tử absolute được đưa ra khỏi luồng bố cục thông thường nên không giữ chỗ ban đầu.

Ví dụ trực quan

Khung cha có position: relative.
Phần tử relative
absolute

Ví dụ code

.container {
    position: relative;
    min-height: 150px;
  }
  
  .label {
    position: absolute;
    top: 10px;
    right: 10px;
  }
  
  .image {
    position: relative;
    left: 10px;
  }

Ứng dụng responsive và deploy

  • Relative: phù hợp để tạo khung cha làm mốc định vị, hoặc dịch chuyển nhẹ một thành phần mà không làm thay đổi vị trí các thành phần khác.
  • Absolute: phù hợp đặt nhãn trên ảnh, biểu tượng thông báo hoặc nút đóng ở góc hộp nội dung.
  • Khi thiết kế responsive, nên kết hợp Flexbox, Grid, đơn vị %, rem và media query; tránh cố định quá nhiều tọa độ bằng pixel.
  • Hai thuộc tính này không phụ thuộc nhà cung cấp hosting. Tuy nhiên, giao diện bố trí không phù hợp có thể bị tràn hoặc chồng lấn trên điện thoại, máy tính bảng và máy tính.
Kết luận: Relative giữ vị trí trong luồng tài liệu và dịch chuyển từ vị trí gốc; absolute định vị theo phần tử cha phù hợp và không giữ chỗ trong luồng.

Đăng ký domain và cấu hình hosting

1. Domain, hosting và DNS

Domain là tên miền của website, ví dụ: shopgiay.com. Hosting là nơi lưu trữ các tệp website như HTML, CSS, JavaScript và hình ảnh. DNS (Domain Name System) có nhiệm vụ phân giải tên miền thành địa chỉ IP hoặc định tuyến đến dịch vụ hosting tương ứng.

2. Quy trình thực hiện

  1. Chọn tên miền phù hợp và kiểm tra tên miền còn khả dụng.
  2. Đăng ký tên miền tại nhà đăng ký được công nhận.
  3. Chuẩn bị website gồm các tệp HTML, CSS, JavaScript và tài nguyên liên quan.
  4. Đưa mã nguồn lên dịch vụ hosting tĩnh như GitHub Pages hoặc Netlify.
  5. Cấu hình DNS theo hướng dẫn của nền tảng hosting, thường là bản ghi A, AAAA, CNAME hoặc bản ghi được nhà cung cấp yêu cầu.
  6. Bật HTTPS, kiểm tra website trên nhiều trình duyệt và thiết bị.

3. Công cụ deploy không cần server riêng

  • GitHub Pages: lưu trữ website tĩnh trực tiếp từ repository GitHub, phù hợp với dự án HTML, CSS và JavaScript cơ bản.
  • Netlify: hỗ trợ deploy từ Git repository hoặc tải thư mục website lên; có thể tự động cập nhật khi mã nguồn thay đổi.

4. Rủi ro bảo mật

  • Không bật HTTPS có thể khiến dữ liệu truyền tải dễ bị nghe lén hoặc can thiệp.
  • Đưa API key, mật khẩu hoặc thông tin bí mật vào JavaScript phía trình duyệt khiến người khác có thể xem được.
  • Cấu hình DNS sai có thể khiến website không truy cập được hoặc trỏ đến máy chủ không mong muốn.
  • Phân quyền repository và tài khoản hosting không an toàn có thể dẫn đến việc mã nguồn bị sửa đổi trái phép.
Kết luận: Domain giúp người dùng truy cập website dễ dàng, DNS kết nối tên miền với hosting, còn hosting lưu trữ và phân phối nội dung website.

So sánh let, const và var trong JavaScript

1. So sánh

  • var: có phạm vi function hoặc global, cho phép khai báo lại và có cơ chế hoisting với giá trị ban đầu là undefined.
  • let: có phạm vi block, không cho khai báo lại cùng tên trong cùng scope; được hoisting nhưng không thể truy cập trước dòng khai báo do Temporal Dead Zone.
  • const: có phạm vi block, phải được gán giá trị khi khai báo và không thể gán lại biến. Với object hoặc array, nội dung bên trong vẫn có thể thay đổi.

2. Ví dụ lỗi thường gặp

console.log(message); // ReferenceError
  let message = "Xin chào";
  
  // Ví dụ khác:
  const age = 20;
  // age = 21; // TypeError: không thể gán lại const

Ở ví dụ đầu, biến message được truy cập trước khi khai báo let nên phát sinh ReferenceError. Ở ví dụ thứ hai, age được khai báo bằng const nên không thể gán lại giá trị.

3. Cách debug bằng Chrome DevTools

  1. Mở website trên Chrome và nhấn F12 hoặc Ctrl + Shift + I.
  2. Chọn tab Console để xem thông báo lỗi và dòng code gây lỗi.
  3. Chọn tab Sources, mở tệp JavaScript cần kiểm tra.
  4. Nhấp vào số dòng để đặt breakpoint, sau đó tải lại trang hoặc thực hiện thao tác gây lỗi.
  5. Dùng Step over, Step into và bảng Scope để theo dõi giá trị biến trong từng bước.
Khuyến nghị: Ưu tiên dùng const khi không cần gán lại biến và dùng let khi giá trị cần thay đổi. Hạn chế dùng var trong mã JavaScript hiện đại.

Event Delegation trong JavaScript

Event Delegation (ủy quyền sự kiện) là kỹ thuật gắn một trình xử lý sự kiện vào phần tử cha thay vì gắn riêng lẻ cho từng phần tử con. Khi người dùng thao tác với phần tử con, sự kiện thường lan truyền lên phần tử cha thông qua cơ chế bubbling. Phần tử cha kiểm tra event.target để xác định phần tử phát sinh sự kiện.

Ví dụ danh sách động

Thử thêm mục mới hoặc nhấn nút Xóa. Chỉ có một trình xử lý click được gắn vào danh sách, vì vậy các mục được thêm sau vẫn hoạt động.

  • Học HTML
  • Thực hành CSS

Code JavaScript minh họa

const taskList = document.getElementById("taskList");
  
  // Chỉ đăng ký một sự kiện click trên phần tử cha
  taskList.addEventListener("click", function(event) {
    if (event.target.matches('[data-action="delete"]')) {
      event.target.closest("li").remove();
    }
  });

Lợi ích khi kết hợp HTML, CSS và JavaScript

  • Giảm số lượng event listener cần đăng ký, đặc biệt với danh sách có nhiều phần tử.
  • Các phần tử được thêm vào sau vẫn có thể sử dụng sự kiện mà không cần đăng ký listener mới.
  • HTML đảm nhiệm cấu trúc danh sách, CSS đảm nhiệm giao diện, JavaScript xử lý tương tác.
  • Mã nguồn gọn hơn, dễ bảo trì và phù hợp với giao diện có nội dung thay đổi liên tục.
Kết luận: Event Delegation tận dụng cơ chế bubbling để xử lý sự kiện tập trung ở phần tử cha, giúp quản lý danh sách động hiệu quả hơn.
